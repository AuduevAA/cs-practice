Рабочая папка
Это твоя обычная папка с файлами проекта на компьютере — там ты пишешь код и меняешь файлы. Git следит за этой папкой и видит, что в ней меняется, но пока ничего не запоминает навсегда.

Индекс
Это как «корзина для отправки»: сюда ты складываешь только те изменения, которые точно хочешь сохранить. Делается это командой git add. Пока файлы в индексе — их можно ещё убрать или добавить новые, коммита ещё нет.

Коммит
Это «сохранённая версия» проекта. Когда ты делаешь git commit, Git берёт всё из индекса и фиксирует как отдельный снимок истории. К нему добавляют короткое описание (например, «добавил главную страницу»), и у снимка появляется свой уникальный номер, чтобы потом к нему вернуться.

Git и GitHub: в чём разница
Git — это программа на твоём компьютере, которая запоминает, как менялся проект. Работает без интернета: ты сам делаешь версии (коммиты), смотришь историю.

GitHub — это сайт, куда можно выложить копию проекта, чтобы другие её видели и помогали править.

Использованные команды

git status
Показывает, что происходит с файлами: какие изменились, какие новые, какие уже готовы к коммиту. Ещё пишет, на какой ветке ты сейчас. Это как быстрая проверка перед сохранением.

git diff
Показывает изменения, которые ты сделал, но ещё не подготовил (до git add). То есть: «что поменялось в файлах прямо сейчас».

git diff --staged
Показывает то, что уже подготовлено для коммита (после git add). То есть: «что именно уйдёт в историю, если сделать коммит сейчас».

## Ветки

**Что такое ветка**
Ветка — это отдельная линия истории проекта. Представь, что ты пишешь черновик: одна версия — для основной работы, а в другой пробуешь смелые идеи. Вот эти разные версии и есть ветки. По умолчанию в проекте обычно есть ветка `main` (или раньше её называли `master`).

**Что происходит с веткой при новом коммите**
Когда ты делаешь коммит, ветка «переезжает» вперёд и теперь указывает на этот новый коммит. То есть ветка — это не набор файлов, а скорее указатель на самый свежий снимок истории. Пока ты на одной ветке, все новые коммиты добавляются именно к ней, а другие ветки остаются на своих старых точках.

**Что делает слияние**
Слияние (merge) — это когда ты берёшь изменения из одной ветки и добавляешь их в другую. Например, ты разработал новую функцию в отдельной ветке, протестировал её, а потом «встраиваешь» эти правки в основную ветку `main`. После слияния в общей истории видно, что эти изменения стали частью проекта, и дальше можно двигаться дальше уже с ними.
